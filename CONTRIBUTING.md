# Guide de contribution - QuartierAlert

Merci de contribuer à QuartierAlert ! Ce guide décrit le processus pour collaborer efficacement.

## Principes
- Code propre, lisible et compréhensible par des débutants
- Documentation à jour
- Pas de secrets dans le dépôt
- Proposition vérifiable par un humain pour toute suggestion IA

## Processus
1. Créer une issue pour discuter du changement
2. Créer une branche depuis `main` : `feat/nom-fonctionnalite` ou `fix/nom-correctif`
3. Développer en suivant les conventions
4. Tester localement
5. Ouvrir une Pull Request avec description complète
6. Demander une revue
7. Fusion après validation

## Conventions de commit
- `feat:` nouvelle fonctionnalité
- `fix:` correction de bug
- `docs:` documentation uniquement
- `test:` ajout/modification de tests
- `refactor:` refactorisation sans changement fonctionnel
- `chore:` maintenance/configuration

## Qualité
- Respecter l'indentation (2 espaces)
- Ajouter des commentaires uniquement si nécessaire
- Valider les entrées côté backend
- Ne pas exposer de clés API côté frontend
